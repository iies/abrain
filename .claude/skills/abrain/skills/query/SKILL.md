# abrain:query

질문: `$ARGUMENTS` (비어 있으면 무엇을 알고 싶은지 묻는다)

규칙은 `AGENTS.md`의 **query**와 "정정"을 따른다. 이 스킬은 검색 순서와 답 형식을 더한다. 위키는 읽기만 한다. 사람이 "저장해줘"라고 하거나 내용을 정정할 때만 쓴다.

## 1. 질문 유형을 정한다

| 유형 | 예 | 주로 볼 곳 |
|---|---|---|
| 대상 하나 | "X 어떻게 돼 가?", "Y는 누구?" | 그 project/person/topic 페이지 전체, 거기서 링크한 결정·source |
| 목록·전체 | "열린 결정 전부", "기한 지난 할 일" | `wiki/` 전체 검색 (frontmatter `status:`, `- [ ]`, `기한`) |
| 언급 찾기 | "X 얘기 나온 적 있어?" | `wiki/sources/` 검색 → 없으면 `raw/_extracted/`, `raw/` |
| 시간 | "지난주에 뭐 정해졌어?" | `wiki/log.md`, source·decision의 `date:` |
| 준비 | "1:1 전에 알아야 할 것" | 사람 페이지 + 관련 프로젝트의 열린 항목·리스크 + 최근 source |

## 2. 찾는다

1. `wiki/프로필.md`(있으면)와 `wiki/index.md`를 읽고 후보 페이지를 고른다. 질문의 "나", "내"는 프로필의 사용자다.
2. 이름과 키워드로 `wiki/`를 검색한다. 용어집의 틀린 표기, 사람 페이지의 `aliases`, 한글/영문, 띄어쓰기 변형까지 넓힌다.
3. 후보 페이지를 열어 읽고, 그 페이지가 링크한 결정·source를 따라간다. 보통 3~5개 페이지면 충분하다.
4. 위키로 부족할 때만 `raw/_extracted/`와 `raw/`를 본다. 원본에서 찾은 내용은 "위키에 아직 반영되지 않음"이라고 밝히고, ingest를 제안한다.
5. "없다", "전부"로 답하기 전에는 반드시 2단계의 변형 검색을 다시 하고 `wiki/` 전체를 grep한다.

근거가 어긋날 때 우선순위: 사용자 정정 > 더 최근 source > 오래된 source. 판단할 수 없으면 양쪽을 인용하고 묻는다.

## 3. 답한다

```
(결론 1~3문장)

- 근거 문장 ([[출처 페이지]], YYYY-MM-DD)
- ...

어긋나는 내용: 없음 | [[A]]는 X, [[B]]는 Y — [[B]]가 최신 (날짜)
확인 안 됨: (위키에 없어서 답하지 못한 부분)
```

- 위키에 없는 것을 일반 지식으로 채우지 않는다. 추론은 "추정:"으로 표시한다.
- 답이 여러 페이지를 종합한 분석·비교라면 마지막에 한 줄로 제안한다: `이 분석을 wiki/topics/에 "제목"으로 저장할까요? ("저장해줘")`
- "저장해줘"면 `wiki/topics/`에 topic 페이지로 쓰고 index와 log를 갱신한다 (`## [날짜] query | 제목`).
- 사람이 "틀렸어"라고 하면 `AGENTS.md` "정정" 절차를 따른다.

마지막으로 `.claude/skills/abrain/scripts/lint-due.sh`를 실행한다. 종료 코드가 1이면 출력된 한 줄을 답 맨 끝에 덧붙인다.
