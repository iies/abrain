# abrain:ingest

입력: `$ARGUMENTS` (비어 있으면 이 대화에서 사용자가 방금 준 텍스트·파일·URL, 그것도 없으면 `raw/`의 미처리 파일 전부)

규칙은 `AGENTS.md`가 유일한 기준이다. 이 스킬은 그 **ingest** 절차를 빠짐없이 실행하기 위한 순서와 보고 형식만 더한다. `AGENTS.md`의 "페이지 규칙", "ingest", "용어 확인", "입력 형식", "회의 녹취록"을 그대로 따르고, 이 문서와 어긋나면 `AGENTS.md`를 따른다.

## 0. 준비

- 오늘 날짜는 추측하지 말고 `date +%Y-%m-%d`로 확인한다.
- `wiki/index.md`, `wiki/용어집.md`를 읽는다.

## 1. 입력 분류

입력이 여러 개면 하나씩 나눠 아래 표로 분류한다. 각 입력은 독립적으로 처리한다. 하나가 실패해도 나머지는 계속한다.

| 입력 | 판별 | 원본 보존 |
|---|---|---|
| raw/의 파일, 로컬 경로 | 경로가 존재한다 | `raw/` 밖이면 `raw/`로 **복사**한다 (원본은 옮기지 않는다). 복사할 수 없으면 `AGENTS.md` ingest 1단계대로 `raw/`에 직접 넣어 달라고 요청한다 |
| URL | `http(s)://` | `AGENTS.md` 입력 형식 표의 YouTube / Google / 웹 URL 행 |
| 회의 내용 (붙여넣기) | 화자, 발언, 안건, 결정이 보인다 | `raw/YYYY-MM-DD 제목.md`에 원문 그대로 저장. 날짜는 회의 날짜, 모르면 오늘 |
| 메모·아이디어 (짧은 글) | 한두 문단의 생각, 할 일, 아이디어 | `raw/YYYY-MM-DD 제목.md`에 원문 그대로 저장. 사람이 쓴 표현을 고쳐 쓰지 않는다 |
| 대상 없음 | 인자도, 대화 속 입력도 없다 | `raw/`에서 어떤 source의 `raw:`에도 없는 파일 (`_extracted/`, `assets/` 제외) |

- 같은 파일명이나 같은 `url:`의 source 페이지가 이미 있으면 새 요약을 만들지 않고 `AGENTS.md`의 "같은 소스가 다시 들어오면" 규칙을 따른다.
- 음성·영상은 전사 전에 `./INSTALL.sh --check-models`를 실행한다. 실패하면 그 파일만 건너뛰고 보고에 안내를 남긴다.
- 대상이 10개를 넘으면 3개만 끝까지 처리해 보고하고, 사람의 확인을 받은 뒤 나머지를 진행한다.

## 2. 쓰기 전 확인 (게이트)

위키에 쓰기 **전에** 입력마다 다음을 끝낸다.

1. **용어 확인** — 용어집과 사람 페이지 `aliases`에 있는 표기는 확정 표기로 바꾼다. 남은 모호한 용어(표기 흔들림, 오인식, 모르는 약어)는 모든 입력에서 모아 **한 번에** 묻는다. 형식:
   ```
   용어 확인 — 아는 것만 답해 주세요 (예: 1=모아, 2=모름)
   1. "모와" — "모와 쪽 일정은 다음 주에 다시 보죠" → 추정: 제품명 "모아"
   2. "JK" — "JK가 승인하면 바로 진행" → 추정: 사람 이름 이니셜
   ```
   답을 받은 뒤 진행한다. 묻는 것은 이 한 번뿐이다.
2. **대상 찾기** — 등장한 사람·프로젝트·주제·결정마다 `wiki/`를 이름, 한글/영문, 띄어쓰기 변형, `aliases`로 검색하고(`grep -ril`), 가장 가까운 페이지를 **열어서 읽는다**. 판정:
   - `기존` — 같은 대상 → 그 페이지를 갱신하고 새 표기를 `aliases`에 더한다.
   - `신규` — 없음, 그리고 이 소스에서 실질적으로 다뤄진다 → 새 페이지.
   - `언급만` — 한 번 스치듯 나온다 → 페이지를 만들지 않고 요약에만 남긴다. 애매하면 만들지 않는다. 나중에 만들 수 있다.

## 3. 쓰기

`AGENTS.md` ingest 4~7단계대로 source 요약 → 전파 → 상충 처리 → index·log 갱신.

- 기존 페이지는 덧붙이지 말고 해당 문단을 현재 상태로 다시 쓴다.
- 메모·아이디어: source 요약은 짧게 쓴다. 아이디어 자체는 관련 project 또는 topic 페이지에 사람의 원래 표현을 인용해 넣는다. 맞는 페이지가 없고 아이디어가 독립된 주제일 때만 `wiki/topics/`에 새로 만든다.
- 회의: 결정과 논의를 구분하고, 화자 추정과 참여자 표 규칙을 지킨다.

## 4. 보고

아래 형식으로 끝낸다. 비어 있는 칸은 "없음"으로 쓴다.

```
ingest 완료 — 입력 N개 (성공 n, 건너뜀 m)

핵심
- (3~5줄)

| 입력 | 종류 | 요약 페이지 | 결과 |
|---|---|---|---|
| raw/2026-11-12 주간 회의.m4a | 회의(음성) | [[2026-11-12 주간 리더십 회의]] | 완료 |

페이지
- 생성: [[...]] (신규 판정 근거 한 줄)
- 갱신: [[...]] (무엇이 바뀌었나)
- 언급만 (페이지 미생성): 이름, 이름

상충: 없음 | > 이전 → 현재 (출처)
실패·잘림: 없음 | 파일 — 명령 — 오류
질문: 없음 | (용어 미확인, 판단 불가한 상충 등)
```

회의 녹취록이면 그 뒤에 `AGENTS.md`의 "발언자 확인" 질문을 붙인다.

마지막으로 `.claude/skills/abrain/scripts/lint-due.sh`를 실행한다. 종료 코드가 1이면 출력된 한 줄을 보고 맨 끝에 덧붙인다.
