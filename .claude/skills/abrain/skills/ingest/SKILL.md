# abrain:ingest

입력: `$ARGUMENTS` (비어 있으면 이 대화에서 사용자가 방금 준 텍스트·파일·URL, 그것도 없으면 `raw/`의 미처리 파일 전부)

공통 규칙은 `AGENTS.md`가 기준이다. 이 스킬은 그 **ingest** 절차를 빠짐없이 실행하기 위한 순서와 보고 형식, 그리고 형식별 변환과 음성 전사 규칙을 담는다. `AGENTS.md`의 "페이지 규칙", "ingest", "용어 확인", "회의 녹취록"을 그대로 따른다. 형식별 변환과 음성 전사는 이 문서의 "입력 형식", "음성 전사 실행 규칙"이 기준이다 (`AGENTS.md`에서 옮겨 왔다). 공통 규칙이 이 문서와 어긋나면 `AGENTS.md`를 따른다.

## 0. 준비

- 오늘 날짜는 추측하지 말고 `date +%Y-%m-%d`로 확인한다.
- `wiki/프로필.md`(있으면), `wiki/index.md`, `wiki/용어집.md`를 읽는다. 프로필의 사용자와 답변 선호는 `AGENTS.md`의 "프로필 사용"대로 쓴다.

## 1. 입력 분류

입력이 여러 개면 하나씩 나눠 아래 표로 분류한다. 각 입력은 독립적으로 처리한다. 하나가 실패해도 나머지는 계속한다.

| 입력 | 판별 | 원본 보존 |
|---|---|---|
| raw/의 파일, 로컬 경로 | 경로가 존재한다 | `raw/` 밖이면 `raw/`로 **복사**한다 (원본은 옮기지 않는다). 복사할 수 없으면 `AGENTS.md` ingest 1단계대로 `raw/`에 직접 넣어 달라고 요청한다 |
| URL | `http(s)://` | 아래 "입력 형식" 표의 YouTube / Google / 웹 URL 행 |
| 회의 내용 (붙여넣기) | 화자, 발언, 안건, 결정이 보인다 | `raw/YYYY-MM-DD 제목.md`에 원문 그대로 저장. 날짜는 회의 날짜, 모르면 오늘 |
| 메모·아이디어 (짧은 글) | 한두 문단의 생각, 할 일, 아이디어 | `raw/YYYY-MM-DD 제목.md`에 원문 그대로 저장. 사람이 쓴 표현을 고쳐 쓰지 않는다 |
| 대상 없음 | 인자도, 대화 속 입력도 없다 | `raw/`에서 어떤 source의 `raw:`에도 없는 파일 (`_extracted/`, `assets/` 제외) |

- 같은 파일명이나 같은 `url:`의 source 페이지가 이미 있으면 새 요약을 만들지 않고 `AGENTS.md`의 "같은 소스가 다시 들어오면" 규칙을 따른다.
- 음성·영상은 전사 전에 `./INSTALL.sh --check-models`를 실행한다. 실패하면 그 파일만 건너뛰고 보고에 안내를 남긴다.
- 대상이 10개를 넘으면 3개만 끝까지 처리해 보고하고, 사람의 확인을 받은 뒤 나머지를 진행한다.

## 2. 쓰기 전 확인 (게이트)

위키에 쓰기 **전에** 입력마다 다음을 끝낸다.

1. **용어 확인** — 용어집과 사람 페이지 `aliases`에 있는 표기는 확정 표기로 바꾼다. 남은 모호한 용어(표기 흔들림, 오인식, 모르는 약어)는 모든 입력에서 모아 **한 번에** 묻는다. 형식:
   ```
   용어 확인 — 아는 것만 답해 주세요 (예: 1=모아, 2=모름)
   1. "모와" — "모와 쪽 일정은 다음 주에 다시 보죠" → 추정: 제품명 "모아"
   2. "JK" — "JK가 승인하면 바로 진행" → 추정: 사람 이름 이니셜
   ```
   답을 받은 뒤 진행한다. 묻는 것은 이 한 번뿐이다.
2. **대상 찾기** — 등장한 사람·프로젝트·주제·결정마다 `wiki/`를 이름, 한글/영문, 띄어쓰기 변형, `aliases`로 검색하고(`grep -ril`), 가장 가까운 페이지를 **열어서 읽는다**. 판정:
   - `기존` — 같은 대상 → 그 페이지를 갱신하고 새 표기를 `aliases`에 더한다.
   - `신규` — 없음, 그리고 이 소스에서 실질적으로 다뤄진다 → 새 페이지.
   - `언급만` — 한 번 스치듯 나온다 → 페이지를 만들지 않고 요약에만 남긴다. 애매하면 만들지 않는다. 나중에 만들 수 있다.

## 3. 쓰기

`AGENTS.md` ingest 4~7단계대로 source 요약 → 전파 → 상충 처리 → index·log 갱신. source 요약은 `wiki/5 자료/종류/YYYY/`에 쓴다 (종류는 `AGENTS.md` "세 개의 층"의 표).

- 기존 페이지는 덧붙이지 말고 해당 문단을 현재 상태로 다시 쓴다.
- 메모·아이디어: source 요약은 짧게 쓴다. 아이디어 자체는 관련 project 또는 topic 페이지에 사람의 원래 표현을 인용해 넣는다. 맞는 페이지가 없고 아이디어가 독립된 주제일 때만 `wiki/4 주제/`에 새로 만든다.
- 회의: 결정과 논의를 구분하고, 화자 추정과 참여자 표 규칙을 지킨다.

## 4. 보고

아래 형식으로 끝낸다. 비어 있는 칸은 "없음"으로 쓴다.

```

핵심
- (3~5줄)

| 입력 | 종류 | 요약 페이지 | 결과 |
|---|---|---|---|
| raw/2026-11-12 주간 회의.m4a | 회의(음성) | [[2026-11-12 주간 리더십 회의]] | 완료 |

페이지
- 생성: [[...]] (신규 판정 근거 한 줄)
- 갱신: [[...]] (무엇이 바뀌었나)
- 언급만 (페이지 미생성): 이름, 이름

상충: 없음 | > 이전 → 현재 (출처)
```

회의 녹취록이나 발언자 이름이 빠진 대화 캡처면 그 뒤에 아래 "참석자 확인 형식"대로 참석자 확인 질문을 붙인다.

마지막으로 `.claude/skills/abrain/scripts/lint-due.sh`를 실행한다. 종료 코드가 1이면 출력된 한 줄을 보고 맨 끝에 덧붙인다.

## 입력 형식

| 입력 | 방법 |
|---|---|
| txt, md, csv, json, vtt, srt | 그대로 읽는다. |
| docx, pptx, xlsx, pdf, html, eml, epub | `markitdown 파일` |
| pptx·docx·xlsx 안의 그림 | 변환 결과에 그림이 파일명으로만 남으면 `unzip -o -j 파일 'ppt/media/*' -d raw/_extracted/원본파일명/` (docx는 `word/media/*`, xlsx는 `xl/media/*`)로 꺼내 직접 본다. 로고와 장식은 무시한다. |
| pdf (스캔본, 그림 위주) | 텍스트가 비어 있거나 도표가 중요하면 `pdftoppm -r 80 -png 파일 raw/_extracted/원본파일명/p`로 페이지를 이미지로 만들어 직접 본다. |
| png, jpg, gif, webp | 직접 본다. 읽은 내용을 요약 페이지에 적는다. |
| heic, tiff, bmp | `ffmpeg -i 파일 raw/_extracted/원본파일명.png` 후 직접 본다. |
| hwp | `hwp5html --html --output raw/_extracted/원본파일명.html 파일` 후 `markitdown`으로 변환한다. |
| hwpx | `unzip -p 파일 'Contents/section*.xml'` 출력에서 `<hp:t>` 태그의 텍스트를 뽑는다. |
| doc, rtf, odt | `textutil -convert txt -stdout 파일` |
| 음성 (mp3, wav, m4a, ogg, flac), 영상 (mp4, mkv, mov, webm) | 먼저 `./INSTALL.sh --check-models`로 음성 인식 모델이 있는지 확인한다. 실패하면 전사하지 않는다. 모델을 직접 받지 말고, 그 파일은 건너뛰고 나머지를 계속 처리한다. 보고에 "음성 인식 모델이 설치되어 있지 않습니다. 터미널에서 `./INSTALL.sh --models`를 실행해 모델(약 4.6GB)을 받은 뒤 다시 ingest 해 주세요."라고 안내하고 건너뛴 파일을 적는다. 모델이 있으면 아래 "음성 전사 실행 규칙"을 따른다. |
| 영상 속 화면 (화면 공유, 발표 자료) | 화면 내용이 중요하면 `ffmpeg -i 파일 -vf "select='eq(n,0)+gt(scene,0.3)'" -fps_mode vfr raw/_extracted/원본파일명/f-%03d.jpg`로 장면을 뽑아 직접 본다. |
| YouTube URL | 먼저 `yt-dlp --list-subs URL`로 자막을 확인한다. 영상의 원래 언어 자막이 있으면 (사람이 올린 자막 우선, 없으면 자동 자막) `yt-dlp --skip-download --write-subs --write-auto-subs --sub-langs 언어코드 --convert-subs srt -o "raw/%(upload_date>%Y-%m-%d)s %(title)s" URL`로 받는다. 번역 자막은 요청하지 않는다 (차단된다). 자막이 없으면 `yt-dlp -x --audio-format mp3 -o "raw/%(upload_date>%Y-%m-%d)s %(title)s.%(ext)s" URL`로 음성을 받아 음성 파일과 같이 처리한다. 영상 파일 자체는 받지 않는다. |
| Google Docs·Slides·Sheets URL | 연결된 Google Drive 도구로 내보내 `raw/YYYY-MM-DD 제목.확장자`로 저장한다 (Slides는 pdf, Docs는 docx, Sheets는 xlsx). 도구가 파일을 다른 위치에 저장하면 `raw/`로 복사하고, 다운로드 URL을 돌려주면 `curl`로 받는다. 도구가 없거나 실패하면 파일로 내려받아 `raw/`에 넣어 달라고 요청한다. |
| 그 밖의 웹 URL | `curl -sL -A "Mozilla/5.0" URL \| markitdown -x html > "raw/YYYY-MM-DD 제목.md"`. 본문이 비었거나 로그인 화면이면 중단하고 보고한다. |
| 그 밖의 형식 | `markitdown 파일`을 시도한다. 실패하면 보고한다. |

## 음성 전사 실행 규칙

- **Codex의 MLX 전사는 최초 실행부터 샌드박스 밖에서 실행한다.** `exec_command`의 `sandbox_permissions: "require_escalated"`를 지정하고 Metal GPU 접근 목적을 `justification`에 적는다. 샌드박스 안에서 먼저 실행해 실패를 재현하지 않는다. 모델 설치 확인과 원본 복사 등 GPU가 필요 없는 작업은 이 규칙의 대상이 아니다.
- Codex는 `command -v mlx_whisper`로 확인한 실행 파일의 절대 경로로 호출한다. PATH에 없으면 `uv tool dir --bin` 아래에서 찾는다. 명령 허용 규칙과 정확히 일치하도록 전사 명령은 다른 명령이나 환경 변수 할당과 묶지 않은 단독 호출로 실행한다. 다른 환경에서는 실제 실행 파일 경로를 확인하고 해당 경로의 허용 규칙을 사용한다.
- 기본 명령: `<MLX 실행 파일의 절대 경로> 파일 --model mlx-community/whisper-large-v3-mlx --language ko -f all --condition-on-previous-text False --output-dir raw/_extracted/`. Claude Code 등 다른 도구에서는 실행 파일 경로를 환경에 맞게 사용한다. `all` 출력의 시각 정보도 보존해 근거 발언·화자 확인에 사용한다.
- 반복 오류 전파를 줄이기 위해 `--condition-on-previous-text False`를 기본으로 적용한다. 이 옵션이 모든 오인식을 막지는 않으므로 반복·누락·고유명사·숫자를 검토한다. 판독할 수 없는 구간이 결정·숫자·이름처럼 핵심 내용이면 다시 전사하지 않고, 시각과 앞뒤 원문을 붙여 보고의 질문으로 남긴다.
- 샌드박스 밖에서도 `No Metal device` 오류가 나거나 MLX 명령이 없으면 `whisper-ctranslate2 파일 --model large-v3-turbo --language ko --output_format all --condition_on_previous_text False --output_dir raw/_extracted/`로 대체한다. CPU 전사는 GPU 접근을 위한 외부 실행을 요구하지 않는다. 동일 파일을 두 엔진으로 동시에 전체 전사하지 않는다.
- 한국어가 아니면 `--language ko`를 뺀다.
- Codex의 명령 허용 규칙은 `${CODEX_HOME:-$HOME/.codex}/rules/abrain-mlx-whisper.rules`에 둔다. `INSTALL.sh`의 기본 설치와 `--models`가 실제 MLX 경로로 설치하며, 경로 변경이나 기존 설치 환경에서는 `./INSTALL.sh --codex-rules`로 갱신한다. 규칙 변경 뒤 Codex를 재시작한다. 문서 지침과 허용 규칙은 상위 관리 정책·승인 심사를 우회하지 않는다. 외부 실행이 거부되면 거부 사유를 보고하고 허용된 CPU 전사 가능 여부를 확인한다.

## 참석자 확인 형식

`AGENTS.md` 화자 추정의 "참석자 확인" 질문을 이 형식으로 쓴다. ingest, lint, 정정 등 화자를 묻는 모든 작업이 같은 형식을 쓴다. 사람은 시각이나 짧은 조각으로는 발언을 기억하지 못하므로, 듣자마자 "아, 그 말" 하고 떠올릴 발언을 보여준다.

**발언 고르기**
- 참여자마다 2~3개, 회의의 서로 다른 구간(앞·중간·끝)에서 고른다.
- 고르는 순서: ① 결정·확정 선언 ② 숫자·날짜·고유명사가 들어간 발언 ③ 자기 약속("제가 ~까지 ~하겠습니다") ④ 강한 반대·우려·감정이 실린 말 ⑤ 그 회의에서만 나온 특이한 사례·비유 ⑥ 상대 이름을 부르는 말. 맞장구("네", "그렇죠"), 짧은 질문, 진행 멘트("다음으로 넘어가죠"), 어느 회의에서나 나올 일반론은 고르지 않는다.
- 인용은 완결된 문장 1~3개를 전사 원문 그대로 옮긴다. 단어나 구절만 떼어 오지 않는다 (`"뭐가 필요한지"` ✗). 길어도 줄이지 말고, 중간을 생략할 때만 `…`를 쓴다. 오인식이 분명한 단어는 바로 뒤에 `[확정 표기]`를 덧붙인다.
- 인용마다 무슨 얘기 중이었는지 한 줄을 붙인다. 상대의 말에 대한 대답이면 직전 상대 발언을 그 줄에 짧게 넣는다.
- 시각은 인용마다 단일 시각 하나. `28:26–30:02` 같은 범위만으로 근거를 대신하지 않는다.

**라벨**
- 묻는 대상은 언제나 `참여자A`, `참여자B`, `참여자C`… 한 가지로 붙인다. 화자 미상 발언 하나, 이름만 빈 참여자, 여러 회의를 한 번에 물을 때도 ①·②나 회의별 라벨을 섞지 않고 질문 전체에서 A부터 차례로 붙인다.
- 요약 페이지의 기존 라벨(예: 다른 회의의 `참여자A`, `[미상]`)과 다르면, 답을 받아 반영할 때 대응시킨다.

**레이아웃** (코드 블록이나 들여쓴 평문으로 늘어놓지 않는다)
- 맨 위에 무엇을 묻는지와 답하는 법을 한 번만 적는다.
- 회의가 여럿이면 회의마다 `##` 회의 제목 소제목.
- 참여자마다 `### 참여자A · 추정: 이름 · 역할` 소제목.
- 인용마다 `**상황 설명** · 시각` 한 줄, 다음 줄에 `>` 인용 블록.
- 추정 근거와 확신은 참여자 끝에 `*기울임*` 한 줄.
- 참여자 사이는 `---`로 나눈다.

예시:

```markdown
**참석자 확인** — 내용상 3명이 말한 회의로 보입니다. 각 참여자는 누구입니까?
답: `A=홍길동, B=나, C=모름` 한 줄로. 본인은 "나", 인원이 틀렸으면 알려 주세요.

---

### 참여자A · 추정: 김하늘 · 의사결정자

**카톡 연동 범위 얘기에 선을 그으며** · 12:35
> "카톡까지 건드리면 QA가 두 배야. 이번엔 우리 앱 안에서만 해."

**묶음 발송을 언제 내보낼지 정하던 중** · 41:10
> "그러면 묶음 발송은 12월 8일 배포에 넣는 걸로 하자. 확정. 대신 실패율 2% 넘으면 바로 롤백하고."

*근거: 혼자 반말, 결론을 정하는 발언. 확신 높음.*

---

### 참여자B · 추정: 미상 · 제안 발표자

**회의 시작, 묶음 발송 제안을 소개하며** · 00:40
> "지난달 푸시 클릭률이 3.1%까지 떨어졌어요. 하루 다섯 번씩 보내니까 다들 끄는 거죠."

**참여자A가 "근거 데이터 있어?"라고 묻자** · 18:02
> "제가 다음 주 수요일까지 AB 테스트 설계해서 드리겠습니다. 대조군은 기존 발송 그대로 두고요."

---

### 참여자C · 추정: 미상 · 개발 담당

**카톡 연동 일정 질문에 답하며** · 11:50
> "카톡 쪽도 같이 바꾸는 건 좀 생각해 봅시다. 템플릿 심사만 2주 걸려서 12월 8일은 못 맞춰요."
```
