# abrain:onboarding

규칙은 `AGENTS.md`의 **onboarding**(언제 하는지)과 "페이지 규칙", 그리고 아래 "기준 절차"를 따른다. 기준 절차는 `AGENTS.md`에서 옮겨 왔고, 이 스킬의 나머지는 그 절차의 인터뷰 순서, 쓰는 파일, 보고 형식이다. 공통 규칙이 이 문서와 어긋나면 `AGENTS.md`를 따른다.

## 기준 절차

1. **이미 아는 것.** 위키에 사용자에 대한 내용이 있으면 모아서, 다시 묻지 않고 맞는지만 확인한다.
2. **묻기.** 이름과 다른 표기 (한글 실명, 영문명, 영문명의 한글 발음, 성+영문명, 메신저 표시 이름, 오인식 표기), 소속과 역할, 진행 중인 프로젝트, 자주 함께 일하는 사람 (사람마다 같은 표기 묶음), 일하는 지역(모닝 브리핑 날씨용)을 한 번에 묻는다. 답변 선호와 그 밖의 모닝 브리핑 설정은 묻지 않고 나중에 정정으로 받는다. 녹취록·캡처 속 본인은 ingest의 참석자 확인에서 "나"라는 답으로 가려진다. 이름 말고는 답하지 않아도 된다. 빈 항목을 다시 묻지 않는다.
3. **확인.** 정리한 내용과 쓸 페이지를 표로 보여주고 확인을 받는다. 확인 전에는 쓰지 않는다.
4. **쓰기.** 질문과 답을 원문 그대로 `raw/YYYY-MM-DD 온보딩 인터뷰.md`에 저장하고, 그 source 요약을 출처로 사용자·사람·프로젝트 페이지, 용어집, `wiki/프로필.md`를 쓴다. 사람이 직접 꼽은 대상은 한 번 언급이어도 페이지를 만든다. 답에 없는 내용을 추측해 채우지 않는다.
5. **기록과 보고.** index와 log를 갱신하고, 만든 페이지와 비워 둔 항목을 보고한다.

원칙:

- **한 번만 한다.** `wiki/프로필.md`가 있으면 인터뷰하지 않는다.
- **사용자의 말만 쓴다.** 답에 없는 소속, 역할, 관계를 추측해 채우지 않는다. 답하지 않은 항목은 비워 둔다.
- **양식이 아니라 대화로.** 질문은 한 번에 보여주고, 사람은 아는 것만 자유롭게 쓴다. 이미 답한 것은 다시 묻지 않는다.
- **확인 전에는 쓰지 않는다.** 정리한 내용을 읽어주고 확인을 받은 뒤에 `raw/`와 `wiki/`에 쓴다.

## 0. 확인

```bash
date +%Y-%m-%d
test -f wiki/프로필.md && echo DONE
```

- `DONE`이면 멈추고 이렇게만 답한다: `온보딩은 이미 끝났습니다 (wiki/프로필.md, YYYY-MM-DD). 바뀐 내용은 "내 소속이 바뀌었어: ..."처럼 말해 주면 정정으로 반영합니다.` 날짜는 프로필의 `onboarded:`.
- `wiki/`가 없으면 `./INSTALL.sh`를 먼저 실행하라고 안내하고 멈춘다.

## 1. 이미 아는 것 모으기

`wiki/index.md`, `wiki/용어집.md`, `wiki/2 사람/`, `wiki/1 프로젝트/`를 읽는다. 사용자 본인으로 정정된 사람 페이지(`(사용자 정정` 출처로 "이 위키의 사용자"라고 적힌 페이지)가 있으면 사용자 후보로 둔다. 위키가 비어 있으면 건너뛴다.

## 2. 묻기 (한 번)

아래를 그대로 보여준다. 1단계에서 찾은 것이 있으면 질문 위에 `위키에서 이미 찾은 정보` 목록을 붙이고, 그 항목은 "맞는지만 확인해 주세요"로 바꾼다.

```
abrain 온보딩 — 위키가 당신을 알아보고 자료를 더 정확히 정리하도록 기본 정보를 받습니다.
아는 것만 자유롭게 써 주세요. 1번 말고는 건너뛰어도 됩니다. 나중에 말로 고칠 수 있습니다.

1. 이름 — 불리는 이름을 모두 적어 주세요. 같은 사람을 가리키면 = 로 이어 주면 됩니다.
   - 한글 실명 (예: 박우람)
   - 영문명과 한글 발음 표기 (예: Dennis, 데니스)
   - 성과 붙여 부르는 이름 (예: 데니스박, Dennis Park)
   - 메신저·메일 표시 이름 (예: 카카오워크 "박우람 Dennis")
   - 별명, 음성 인식이 잘못 받아 적는 표기
2. 소속과 역할 — 회사·팀, 직책, 맡은 일
3. 진행 중인 프로젝트·제품 — 이름, 한 줄 설명, 내 역할
4. 자주 함께 일하는 사람 — 한 사람에 한 줄. 한글 실명 = 영문명 = 한글 발음 = 다른 호칭, 소속·역할
   (예: 권미진 = Jessie = 제시, 토키토키 기획)
5. 일하는 지역 — 모닝 브리핑의 날씨 확인용 (예: 판교)
```

답을 받으면 항목별로 뽑는다. 한 문장에 여러 항목이 섞여 있어도 나눠 담는다 ("결제 개편 PM이고 하늘님이랑 같이 해요" → 역할, 프로젝트, 사람).

- 1번(이름)이 없으면 그것만 한 번 더 묻는다. 다른 빈 항목은 묻지 않는다.
- **이름 표기 묶기.** 1번과 4번은 사람마다 한글 실명, 영문명, 그 밖의 표기(`aliases`)로 나눈다. `=`, `/`, 쉼표, 괄호로 이어 쓴 표기는 같은 사람이다.
- **빠진 표기 제안.** 사내에서 영문명을 쓰는 사람은 자료에 여러 형태로 나온다. 답에 없는 흔한 변형을 3단계 확인 표에 `제안:`으로 따로 보여주고, 사람이 고른 것만 저장한다. 제안 대상: 영문명의 한글 발음 (Dennis → 데니스), 성+영문명 (데니스박, 박데니스, Dennis Park), 호칭 (우람님, 데니스님), 메신저 표시 형식 (박우람 Dennis). 확인받지 않은 제안은 쓰지 않는다.
- 한글 실명이나 영문명 중 하나만 있으면 3단계 확인에서 다른 하나가 있는지 한 번 묻는다. 없다고 하면 그대로 둔다.
- **날씨 지역 확인.** 5번에 지역을 답했으면 `.claude/skills/abrain/scripts/weather.sh "지역" | head -1`로 날씨가 조회되는지 본다. 실패하거나 첫 줄에 "지명 검색 결과"가 붙어 엉뚱한 곳이 나오면 3단계 확인에서 "가까운 큰 지역 이름(예: 판교, 강남)이나 `위도,경도`로 알려 주세요"라고 한 번 묻는다. 5번을 건너뛰었으면 묻지 않고 비워 둔다 (모닝 브리핑이 서울로 가정하고 바꾸는 법을 안내한다).
- 사람이 답한 표기는 확정 표기다. `AGENTS.md`의 용어 확인을 다시 하지 않는다. 단, 같은 대상의 표기가 답 안에서 흔들리면 3단계 확인에서 함께 묻는다.

## 3. 읽어주고 확인받기

쓰기 전에 정리한 내용을 보여준다. 비어 있는 항목은 "없음"으로 쓴다.

```
이렇게 저장합니다. 고칠 곳만 말해 주세요. 맞으면 "좋아".

| 항목 | 내용 | 위키에 쓰는 곳 |
|---|---|---|
| 이름 | 박우람 / Dennis (별칭: 데니스, 데니스박) 제안: Dennis Park, 우람님 | [[...]] 신규 |
| 소속·역할 | ... | [[홍길동]], 프로필 |
| 프로젝트 | 결제 개편 — ... (내 역할: PM) | [[결제 개편]] 갱신 |
| 사람 | 권미진 / Jessie (별칭: 제시) — ... 제안: 권미진 Jessie | [[...]] 갱신 |
| 일하는 지역 | 판교 (날씨 조회 확인) | 프로필 |

확인할 것: (흔들린 표기, 날씨 조회 실패한 지역. 없으면 생략)
```

`위키에 쓰는 곳`의 신규/갱신은 `AGENTS.md`의 중복 금지 규칙대로 이름, 한글/영문, 띄어쓰기 변형, `aliases`로 `wiki/`를 검색해 정한다. 고칠 곳을 말하면 반영하고 다시 확인받지 않고 진행한다.

## 4. 쓰기

1. **원본.** `raw/YYYY-MM-DD 온보딩 인터뷰.md`에 2단계 질문과 사람의 답을 원문 그대로 저장한다. 3단계에서 고친 내용도 그 아래 `## 확인 단계 수정`에 원문 그대로 붙인다. 정리하거나 고쳐 쓰지 않는다.
2. **source 요약.** `wiki/5 자료/메모/YYYY/YYYY-MM-DD 온보딩 인터뷰.md` (`raw:`, `date:` 오늘). 본문: 한 줄 요약 / 핵심 내용(항목별) / 언급된 페이지 링크. 이 페이지가 아래 모든 사실의 출처다.
3. **사용자 페이지.** `wiki/2 사람/한글실명 영문명.md`(`AGENTS.md` 사람 파일명 규칙)를 만들거나 갱신한다. 이미 다른 이름의 페이지가 있으면 규칙대로 이름을 바꾸고 링크를 모두 고친다. 1번의 다른 표기는 `aliases`에, 2번은 "역할과 소속"과 "담당 영역"에 쓴다. 기존 내용과 어긋나면 `AGENTS.md` 상충 처리를 따른다.
4. **사람·프로젝트.** 3·4번에 나온 대상마다 기존 페이지를 갱신하거나 새로 만든다. 사용자가 일부러 꼽은 대상이므로 한 번 언급이어도 만든다. 단, 이름만 있고 설명·역할·별칭이 하나도 없으면 페이지를 만들지 않고 프로필 목록에만 둔다. 프로젝트의 사용자 역할은 프로젝트 페이지 "관련 사람"에 적는다.
5. **용어집.** 3·4번에서 답한 프로젝트·회사 이름의 변형이 있으면 `| 확정 표기 | 틀린 표기·변형 | 뜻 |`으로 더한다. 뜻 끝에 `([[YYYY-MM-DD 온보딩 인터뷰]])`. 사람 이름의 변형은 용어집이 아니라 그 사람 페이지 `aliases`에 넣는다.
6. **프로필.** `wiki/프로필.md`를 아래 형식으로 쓴다. 다른 페이지에 있는 내용은 되풀이하지 말고 링크와 한 줄만 둔다.
7. **기록.** `wiki/index.md` 맨 위 `## Profile` 섹션에 `- [[프로필]] — 위키 주인의 기본 정보와 선호`를 넣고(섹션이 없으면 만든다), 새 페이지를 해당 섹션에 더한다. `wiki/log.md`에 추가한다:

```
## [YYYY-MM-DD] onboarding | 사용자 프로필
- 원본: raw/YYYY-MM-DD 온보딩 인터뷰.md
- 생성: [[프로필]], [[YYYY-MM-DD 온보딩 인터뷰]], [[...]]
- 갱신: [[...]], [[용어집]], [[index]]
- 상충: 없음 | ...
- 빈 항목: (답하지 않은 질문 번호)
```

`wiki/프로필.md`:

```markdown
---
type: profile
updated: YYYY-MM-DD
onboarded: YYYY-MM-DD
---
# 프로필

이 위키의 주인에 대한 기본 정보다. 에이전트는 ingest와 query를 시작할 때 이 페이지를 읽는다.

## 사용자
- [[이름]] — 소속, 역할 ([[YYYY-MM-DD 온보딩 인터뷰]])

## 진행 중인 프로젝트
- [[프로젝트]] — 한 줄 설명, 사용자 역할 ([[YYYY-MM-DD 온보딩 인터뷰]])

## 자주 함께 일하는 사람
- [[사람]] — 소속·역할 ([[YYYY-MM-DD 온보딩 인터뷰]])

## 답변 선호
- 없음

## 모닝 브리핑 설정
- 지역: 판교 ([[YYYY-MM-DD 온보딩 인터뷰]])
- 꼭 챙길 사람·채널: 없음
- 뺄 채널·발신자: 없음
- 소식: 포함
```

답이 없는 섹션은 지우지 말고 `없음`으로 둔다. 답변 선호와 모닝 브리핑의 지역 외 설정은 인터뷰에서 묻지 않고, 사람이 나중에 말하면 정정으로 채운다. 녹취록·캡처 속 본인은 ingest의 참석자 확인에서 "나"라는 답으로 가려진다.

## 5. 보고

```
온보딩 완료 — wiki/프로필.md

- 사용자: [[이름]] (별칭 n개)
- 생성: [[...]]
- 갱신: [[...]]
- 용어집: n개 추가
- 상충: 없음 | 이전 → 현재 (출처)
- 비워 둔 항목: 없음 | 3. 프로젝트, 5. 지역 — 말로 알려 주면 채웁니다.

다음: 파일을 raw/에 넣고 "ingest", 또는 회의 내용을 붙여넣고 "정리해줘". 내일 아침에는 "모닝".
```

마지막으로 `.claude/skills/abrain/scripts/lint-due.sh`를 실행한다. 종료 코드가 1이면 출력된 한 줄을 보고 맨 끝에 덧붙인다.
