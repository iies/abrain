# abrain 자세한 안내

[README](../README.md)에서 다루지 않은 세부 내용입니다. 필요한 부분만 찾아 읽으세요.

## 위키의 구성

위키는 다섯 가지 페이지로 구성됩니다.

| 페이지 | 담기는 내용 |
|---|---|
| 소스 요약 | 넣은 자료 하나하나의 요약 |
| 결정 | 무엇을 왜 그렇게 정했는지, 검토한 대안 |
| 사람 | 역할, 담당 영역, 최근 입장과 약속 |
| 프로젝트 | 현재 상황, 남은 할 일, 리스크 |
| 주제 | 반복해서 나오는 개념, 비교·분석 |

Obsidian에서 abrain 폴더 안의 `wiki` 폴더를 보관소(vault)로 열면, 페이지 사이의 링크를 눌러 이동하고 그래프로 전체 연결을 볼 수 있습니다. ([Obsidian](https://obsidian.md)은 선택 사항입니다.)

## 사용법

평소 말하듯이 요청하면 됩니다. AI가 말을 알아듣고 아래 네 가지 작업 중 하나를 실행합니다.

| 작업 | 하는 일 |
|---|---|
| **onboarding** (처음 설정) | 처음 한 번, 나에 대한 기본 정보를 받아 위키의 출발점을 만듭니다. |
| **ingest** (넣기) | 자료를 읽고 위키로 정리합니다. |
| **query** (묻기) | 위키를 찾아 질문에 답합니다. 답을 저장하거나 틀린 내용을 고치는 것도 여기에 속합니다. |
| **lint** (점검) | 위키 전체를 훑어 문제를 찾고 고칩니다. |

| 하고 싶은 일 | 이렇게 말합니다 | 실행되는 작업 |
|---|---|---|
| 처음 설정 (한 번) | "온보딩" | onboarding |
| 파일 넣기 | 파일을 대화창에 끌어다 놓고 "정리해줘" | ingest |
| 회의록 넣기 | 내용을 대화창에 붙여넣고 "정리해줘" | ingest |
| 링크 넣기 | "이거 넣어줘 https://..." (웹 문서, YouTube, Google Docs·Slides·Sheets) | ingest |
| 파일 여러 개를 한꺼번에 넣기 | abrain 폴더 안의 `raw` 폴더에 파일들을 넣고 "ingest" | ingest |
| 물어보기 | "결제 개편 건 지금 어디까지 왔지?" | query |
| 답을 위키에 남기기 | 답을 받은 뒤 "저장해줘" | query |
| 틀린 내용 고치기 | "그거 틀렸어, 출시일은 12월 20일이야" (내 소속 등이 바뀌었을 때도 같습니다) | query |
| 위키 점검 | "lint" 또는 "점검해줘" | lint |

말로 하는 대신 명령을 직접 입력해도 똑같이 동작합니다. AI가 요청을 다른 뜻으로 알아들을 때 쓰면 확실합니다.

| 작업 | Claude Code | Codex |
|---|---|---|
| onboarding | `/abrain:onboarding` | `$abrain-onboarding` |
| ingest | `/abrain:ingest` 뒤에 파일, 링크, 내용 (비우면 `raw` 폴더의 새 파일 전부) | `$abrain-ingest` |
| query | `/abrain:query` 뒤에 질문 | `$abrain-query` |
| lint | `/abrain:lint` | `$abrain-lint` |

### 정리 도중 AI가 되묻는 것

- **용어**: 제품명이나 약어의 표기가 흔들리거나 뜻을 알 수 없으면 추측하지 않고 물어봅니다. (예: "모아 / 모와 중 어느 쪽이 맞나요?") 한 번 답하면 용어집에 기록되어 다시 묻지 않습니다. "모르겠다"고 답해도 됩니다. 그러면 `(표기 미확인)`으로 표시해 두고 나중에 다시 묻습니다.
- **발언자**: 화자 표시가 없는 회의 녹음은 정리가 끝난 뒤 주요 발언을 보여주며 누가 한 말인지 묻습니다. `A=홍길동, B=모름`처럼 한 줄로 답하면 됩니다.

### 점검 (lint)

"lint"라고 하면 위키 전체를 훑어 서로 어긋나는 내용, 반영이 안 된 최신 정보, 기한이 지난 할 일, 깨진 링크 등을 찾아 보고합니다. 단순한 문제는 바로 고치고, 판단이 필요한 것은 물어봅니다.
**주 1회 정도**를 권장합니다. 7일 넘게 하지 않으면 알아서 알려 줍니다.

## 넣을 수 있는 것

| 종류 | 형식 |
|---|---|
| 문서 | docx, pptx, xlsx, pdf(스캔본 포함), hwp, hwpx, doc, rtf, odt, html, eml, txt, md, csv |
| 이미지 | png, jpg, gif, webp, heic, tiff, bmp (화이트보드 사진, 스크린샷) |
| 음성 | mp3, wav, m4a, ogg, flac |
| 영상 | mp4, mkv, mov, webm |
| 온라인 | 웹 URL, YouTube, Google Docs·Slides·Sheets |

알아둘 점:

- **회의 녹음은 누가 말했는지 구분하지 못합니다.** 발언자가 중요한 회의는 Zoom, Meet, 클로바노트가 만들어 주는 화자 표시 스크립트를 넣는 편이 정확합니다.
- **녹음 변환에는 시간이 걸립니다.** 사용하는 Mac, 모델과 GPU 사용 여부에 따라 소요 시간이 달라집니다.
- **Google 문서 링크**는 Claude나 Codex에 Google Drive가 연결되어 있어야 가져올 수 있습니다. 연결이 없으면 파일로 내려받아 대화창에 끌어다 놓으세요.
- **문서보안(DRM)이나 암호가 걸린 파일**은 읽지 못합니다. 해제한 파일을 넣으세요.

## 지켜야 할 약속

- **`raw` 폴더는 원본 보관함입니다.** 내가 넣은 자료의 원본이 그대로 쌓입니다. AI는 여기에 원본을 추가만 하고, 이미 있는 파일을 고치거나 지우지 않습니다. 위키 내용의 근거이므로 직접 지우거나 이름을 바꾸지 마세요.
- **`wiki` 폴더는 AI가 쓰는 곳입니다.** 직접 고치지 말고 "이 부분 틀렸어, 고쳐줘"라고 말하세요. 그래야 관련된 다른 페이지까지 함께 고쳐지고 기록이 남습니다.
- **내 자료는 내 컴퓨터의 이 폴더 안에만 저장됩니다.** `raw`와 `wiki`는 공유용 abrain 템플릿에 포함되지 않습니다. 다만 AI가 자료를 읽고 정리하는 과정에서 내용이 Claude 또는 Codex 서비스로 전송되므로, 회사의 AI 도구 사용 정책에 맞는 자료만 넣으세요.

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 설치 중 "Homebrew가 필요합니다" | [brew.sh](https://brew.sh)의 안내대로 Homebrew를 설치한 뒤 `./INSTALL.sh`를 다시 실행합니다. |
| 설치 끝에 "실패한 항목"이 나옴 | `./INSTALL.sh`를 다시 실행합니다. 여러 번 실행해도 안전하며, 이미 설치된 것은 건너뜁니다. |
| "PATH에 … 을 추가했습니다" 안내가 나옴 | 터미널 창을 닫고 새로 엽니다. |
| "음성 인식 모델이 설치되어 있지 않습니다" | 터미널에서 `./INSTALL.sh --models`를 실행한 뒤 다시 "ingest"라고 합니다. |
| "원본을 `raw/`에 저장하지 못했습니다" | 그 파일을 abrain 폴더 안의 `raw` 폴더에 직접 넣은 뒤 "ingest"라고 합니다. |
| "ingest"라고 해도 반응이 평소 챗봇 같음 | abrain 폴더 안에서 `claude`를 실행했는지, 폴더 신뢰를 승인했는지 확인합니다. |


## Codex 설정

Apple Silicon에서는 설치된 MLX 실행 파일의 절대 경로를 **Codex 전역 허용 규칙**에 등록합니다. 모든 프로젝트에서 해당 실행 파일을 샌드박스 밖으로 실행할 수 있게 하며, 상위 관리 정책은 계속 적용됩니다. 설치 후 Codex를 재시작하세요.

이미 설치했다면 `./INSTALL.sh --codex-rules`로 규칙만 추가·갱신할 수 있습니다. 기본 위치는 `~/.codex/rules/abrain-mlx-whisper.rules`이며, `CODEX_HOME`이 있으면 그 폴더를 사용합니다. 내용이 같으면 건너뛰고, 변경 시 기존 파일을 같은 폴더의 `.backup.*` 파일로 보존합니다. 다른 규칙과 전역 `config.toml`은 수정하지 않습니다.

## 더 알고 싶다면 (개발자·고급 사용자용)

abrain은 [Karpathy의 LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 패턴의 최소 구현입니다.
구성은 규칙 문서(`AGENTS.md`), 설치 스크립트(`INSTALL.sh`), 스킬 네 개(`.claude/skills/abrain/`, Codex용 `.agents/skills/`)가 전부이고, Claude Code와 Codex가 같은 규칙을 읽습니다.

- **정리 방식을 바꾸고 싶으면 `AGENTS.md`를 고칩니다.** 페이지 구성, 요약 형식, 질문 규칙이 모두 이 파일에 있습니다. 이 파일이 곧 제품입니다.
- 변환한 텍스트는 `raw/_extracted/`에 따로 저장됩니다.
- Codex의 MLX 전사는 Metal GPU 접근을 위해 샌드박스 밖에서 실행합니다. 외부 실행이 불가능하거나 MLX가 실패하면 CPU 전사를 검토합니다.
